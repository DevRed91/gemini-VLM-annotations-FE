## Corrections to the older assessment

- **Registry wiring is implemented.** Annotation creation registers semantic label, structured metadata, derived search attributes, OBB, and a `cluster`/`point` geometry tag. Removal unregisters; world changes create a fresh per-world registry. [VERIFIED: `src/script.ts:417-467,768-827,581-594`]
- **Metadata persistence is implemented, with a local scope.** Schema-v1 JSON is stored in `localStorage` under a normalized scene-URL key and restores label, description, metadata, pin position, geometry/OBB, and dimensions. It does not persist Gaussian indices/masks, chat history, or graph relations. World switches retain stored records; explicit annotation removal/clear-all removes them. The card’s “Close” button only hides the card. [VERIFIED: `src/spatial/AnnotationMetadataStore.ts:41-58,202-225,256-265,311-320`; `src/script.ts:417-467,543-550,722-726,849-903`]
- **`ObjectMatcher` exists, but it is an annotation search matcher, not object correspondence.** The local chat parser and deterministic matcher support normalized phrase matching, configured synonyms, metadata category/description/synonyms, attribute filters, and ambiguity reporting. Search is limited to annotations in the current scene; it makes no Gemini request and does not use OBB geometry. [VERIFIED: `src/spatial/ObjectMatcher.ts:1-19,187-225,246-309`; `src/chat/ChatController.ts:35-36,70-119`; `src/chat/ChatPanel.ts:53-57`]
- **The newest “compound matching” helper is not active yet.** `src/spatial/morphology.ts` defines `decomposePhrase`, but no source imports or calls it; `ObjectMatcher` still uses whole-phrase matching. The local query parser has separate simple query-side singularization. [VERIFIED: `src/spatial/morphology.ts:93-99`; source reference search; `src/chat/LocalQueryParser.ts:24-29,68-103`]
- **Viewer selection grew.** Search results select canonical annotation IDs and emphasize pins/labels/cards/OBB outlines; selecting one result also smoothly turns the camera toward its tag in place. It does not move/frame the camera or select Gaussians. Gaussian highlighting is opt-in and remains distinct. [VERIFIED: `src/chat/ChatPanel.ts:106-152`; `src/script.ts:289-305,478-540,571-573`]
- **Current geometry path is simpler than the earlier report described.** Sampling returns `Vector3[]`; DBSCAN uses fixed `eps=0.3` by default and keeps the largest cluster; OBB fitting is PCA with an AABB fallback (no upright mode in this branch). Lifting rescans Gaussian centers inside that OBB with an opacity filter; there is no `CandidatePoint` provenance type or covariance-connected component stage. [VERIFIED: `src/script.ts:920-937,952-961`; `src/GeometricContextManager/GeometricContextManager.ts:12-39`; `src/utils/obbFit.ts:4-15,71-80`; `src/utils/clusterLifter.ts:56-60,102-148`; source symbol search]

## Registry evolution, reuse, and next phase

`SpatialObjectRegistry` is now the live scene-node inventory, but it remains a node registry rather than a graph: it stores string IDs, metadata/attributes, and defensive OBB copies; numeric Gaussian mask labels and splat indices are intentionally separate. Preserve that contract and add a relation layer keyed by registry IDs instead of changing node identity or `ObjectMatcher`’s geometry-blind behavior. `src/spatial/types.ts:55-88` already distinguishes fitted cluster geometry from pin-only point annotations. [VERIFIED: `src/utils/spatialObjectRegistry.ts:74-97,152-190`; `src/spatial/types.ts:55-88`; INFERRED: additive graph design]

Reuse `src/GeometricContextManager/GeometricContextManager.ts` for sampled-point DBSCAN, `src/utils/obbFit.ts` and `obb.ts` for node bounds, `src/utils/spatialObjectRegistry.ts` for semantic nodes, `src/spatial/AnnotationMetadata.ts` and `AnnotationMetadataStore.ts` for metadata lifecycle, and `src/chat/ChatController.ts` / `src/viewer/ChatAnnotationSelection.ts` for query-to-viewer selection.

**Smallest next VLSplat-aligned phase [INFERRED]:** add a derived spatial-relation layer over current registry nodes, initially connecting only `cluster` OBB nodes whose expanded bounds overlap; exclude `point` fallbacks. Keep edges in memory and rebuild them on registry changes. This fills the missing graph structure of §3.2 without changing persistence or Gaussian selection. Relation-language queries can follow. It is not VLSplat’s learned codebook or §3.3 refinement.
